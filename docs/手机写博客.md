# 用手机写博客：写作台使用说明

「箱中世界」这个博客是 Astro 静态站，文章就是仓库里的 Markdown 文件。写作台是一个开在手机浏览器里的网页，不用装 App、不用碰命令行：写字、选图、点保存，文章就会提交到 GitHub；Netlify 随后自动构建，大约 1 分钟后站点更新。

- 站点：https://lastembryo.netlify.app/
- 写作台入口：https://lastembryo.netlify.app/admin/
- 仓库：`chenjing185/My_blog_website`（分支 `main`）
- 文章目录：`src/content/blog/`
- 图片目录：`public/uploads/YYYY-MM/`

第一次用需要三样东西：一台能上网的手机、你的 GitHub 账号（对上面这个仓库有写权限）、一个新生成的访问令牌。全程大约 5 分钟。

---

## 1. 生成 GitHub 访问令牌（只需做一次）

写作台通过 GitHub 官方 API 读写仓库，需要一个「细粒度令牌」（fine-grained PAT）。可以把它理解成一把专用钥匙：只能开这一个仓库，只能改文件内容。

最省事的入口：手机浏览器打开 <https://github.com/settings/personal-access-tokens/new>（登录 GitHub 后会直接跳到创建页面）。也可以从下面第 1 步的菜单一层层点进去。

1. 手机浏览器打开 <https://github.com> 并登录（chenjing185 本人，或对该仓库有写权限的账号）。
2. 点右上角头像 →「Settings」。
3. 页面拉到最下面，点「Developer settings」。
4. 点「Personal access tokens」→「Fine-grained tokens」。
5. 点右上角「Generate new token」。
6. 按下面这张表填写：

| 项目 | 应该选 |
| --- | --- |
| Token name | `lastembryo-blog-mobile`（随便起，能认出来就行） |
| Expiration | 建议 90 天，到期重新生成；也可以选自定义日期 |
| Resource owner | `chenjing185` |
| Repository access | 选「Only select repositories」，只勾 `chenjing185/My_blog_website` |
| Repository permissions → Contents | **Read and write** |
| Repository permissions → Metadata | Read-only（勾了 Contents 后自动变成这样，不用改） |
| 其他所有权限 | 保持「No access」 |

> 如果仓库不是你自己的（你只是协作者），「Resource owner」选**你自己的账号**，仓库仍然只勾 `chenjing185/My_blog_website`；前提是你的账号对这个仓库有写权限。

7. 拉到页面最下面，点「Generate token」。
8. 复制 `github_pat_` 开头的那一长串。它**只显示这一次**，关掉页面就看不到了；先粘贴到手机备忘录，下一步马上要用。

注意事项：

- 不要选「All repositories」或「Public repositories」——权限范围越小越安全。
- 没复制下来就删掉这个令牌，重新生成一个。
- 不要把令牌发到群里、写进文章或截图里。

## 2. 把写作台放到手机主屏幕

每次输网址太麻烦，添加到主屏幕后就像打开一个 App。

**iPhone / iPad（Safari）**

1. 用 Safari 打开 <https://lastembryo.netlify.app/admin/>。
2. 点「分享」按钮（方框 + 向上箭头；iPhone 在屏幕下方，iPad 在屏幕上方）。
3. 在弹出的菜单里往下滑，点「添加到主屏幕」。
4. 名称改成「写作台」，点「添加」。
5. 以后从桌面图标直接进入。

**Android（Chrome / Edge）**

1. 用浏览器打开同一个网址。
2. 点右上角「⋮」→「添加到主屏幕」（有的版本写「安装应用」或「添加到主屏幕」）。
3. 确认名称后点「添加」。

> 写作台自带 Service Worker，Android Chrome 有时会直接弹出「安装应用」，点一下更省事；没有弹窗就用上面「添加到主屏幕」。装好后即使断网也能打开它、看到本机草稿。
>
> 如果打开 `/admin/` 是 404：说明当前线上版本里还没有写作台，先等 Netlify 构建成功再试（见第 9 节「故障排查」）。

## 3. 第一次连接

1. 打开写作台，首次会看到「连接你的 GitHub 仓库」。
2. 在「访问令牌（Personal Access Token）」输入框里，粘贴第 1 步复制的令牌。
3. 点「连接并开始」。
4. 看到文章列表就说明连接成功，之后不用再输令牌。

- 令牌只保存在这台手机浏览器的本地存储（localStorage）里，不会写进仓库，也不会随文章提交。
- 换手机、换浏览器或清理浏览器数据后，需要重新连接一次。
- 忘了怎么生成？连接页里有可展开的「怎么生成令牌？」，拉下来看第 1 节也一样。

> 想先空手试试：在网址后面加 `?demo=1`（<https://lastembryo.netlify.app/admin/?demo=1>），进入演示模式——可以点新建、改文章、试图片，但不会联网，也不会写你的仓库。熟悉了再按上面的步骤连接。

> 连接页最下面还有一块「高级选项」：仓库所有者、仓库名、分支、文章目录。留空就用本站默认值；只有要写别的仓库（或换分支）时才需要填。

### 3.1 之后想改设置

点右上角齿轮「⚙」进入设置页：

- 可以改仓库 owner / 仓库名 / 分支 / 文章目录（一般不用动，默认就是 `chenjing185/My_blog_website`、`main`、`src/content/blog`）。
- 「测试连接」会校验令牌并列出目录里的文章数量，出错会显示原因。
- 「保存」只保存设置并重新连接，不会提交文章。
- 「Netlify 站点名」是可选项（例如 `lastembryo`），填了以后设置页会多一个「打开 Netlify 部署记录」的链接，保存完想确认构建状态很方便。
- 「断开连接」只清掉这台手机里的令牌，仓库里的文章和本机草稿都不受影响；换新令牌或要借别人手机用时点它。

## 4. 认识列表页

进入写作台后看到的就是文章列表。

- 顶部栏右侧：「↗」在新标签打开站点首页，「◐」切换白天/夜间，齿轮「⚙」打开设置（改仓库/分支/目录/令牌，或点「测试连接」）。
- 列表工具栏：搜索框、「刷新」「新建」；列表上方会显示「共 N 篇 · 更新时间」。
- 搜索框：输入标题、摘要或标签，筛选出匹配的文章；只是查看，不会改仓库。
- 卡片角标：「草稿」「置顶」。
- 列表上方如果出现「本机有未保存的草稿」，说明这台手机上还有没提交的内容（可能是在别处断网、或返回列表时自动留下的）。每条都能「继续写」或「丢弃」，右边「全部丢弃」一次清空。
- 还没有文章时，会显示「还没有文章，点右上角『新建』开始写吧」。
- 点任意一张卡片，就打开这篇文章的编辑器。
- 如果在电脑上或别的设备改过文章，先点「刷新」再编辑，避免撞上 409 冲突。

## 5. 写一篇新文章

### 5.1 打开编辑器

点「新建」，进入空白编辑器。编辑器顶部是「返回」和「保存」；正文工具条右边有「预览」；编辑已有文章时，页面底部还会出现「查看 GitHub 文件」和「删除文章」。

> 写一半要离开也没关系：写作台会自动在本机存一份草稿，下次打开这篇文章会弹「有未保存的本地草稿」，选「恢复」就能接着写；选「丢弃」则从仓库版本重新开始。**草稿是按文章分开存的**，写完 A 又去改 B，A 的草稿不会被 B 覆盖；列表页顶部会把它们都列出来。这份草稿只在这台手机上，不会提交到仓库。
>
> 保存时如果网络断了，内容也会自动转成草稿存下来；等有网了打开这篇点「恢复」，接着点保存就行。

### 5.2 填写表单

打开编辑器先看到常用字段；分类、标签、专栏、文件名、封面、外链、副标题都收在「更多设置」里，点一下展开。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 标题 | ✅ | 最长 **120 字**，超了保存会失败（构建同样报错） |
| 摘要 | ✅ | 最长 **300 字**，超了保存会失败；列表卡片、搜索、RSS、分享都用它 |
| 发布日期 | ✅ | 默认今天，点日期框选择即可 |
| 更新日期 | | 可以空着；填了文章页会显示「更新于」 |
| 分类（更多设置） | | 单值，例如 `随笔`、`技术` |
| 标签（更多设置） | | 用逗号分隔（中英文逗号都行），例如 `随笔, 手机`；会自动生成标签页 |
| 专栏（更多设置） | | 同名文章自动聚合成专栏，并显示「第几篇 / 共几篇」 |
| 文件名（更多设置） | | **决定网址，别轻易改**，见 5.3 |
| 封面图（更多设置） | | 输入框 +「上传封面」按钮；列表缩略图和分享图都用它 |
| 外链（更多设置） | | 可选；填了之后列表直接跳外链，正文只做导读 |
| 副标题（更多设置） | | 可选，显示在标题下面 |
| 存为草稿 | | 开关，见 7.2 |
| 置顶 | | 开关，打开后会排在首页和列表最前面 |

### 5.3 文件名就是网址

文章最终保存在 `src/content/blog/<文件名>.md`，网址是 `/blog/<文件名>/`。

新建时会按标题自动生成一个默认文件名：英文标题直接用标题（如 `my-trip`）；纯中文标题会得到 `post-20261110-1650` 这样的名字。都可以在「更多设置」里改。

例如文件名写成 `2026-11-10-my-trip`，发布后地址就是：

```
https://lastembryo.netlify.app/blog/2026-11-10-my-trip/
```

建议用**英文、数字和短横线**。中文也能用（页面上显示中文，但复制出来的链接是一串百分号编码），想稳妥分享就尽量用英文。

### 5.4 写正文

正文用 Markdown，工具条从左到右是：标题、粗体、斜体、列表、引用、代码、链接、图片、分隔线。点按钮会给选中的文字套上对应的标记。最常用的写法：

```markdown
## 二级小标题

**粗体**、*斜体*、`行内代码`

- 列表项
- 另一项

> 引用一段话

[链接文字](https://example.com)

![图片说明](/uploads/2026-11/1712345678901-cat.jpg)

---
```

正文下方会实时显示字数，写长了你心里有数。

### 5.5 插入图片

1. 把光标放到要插图的位置。
2. 点工具条上的「图片」。
3. 从手机相册选一张图。
4. 浏览器会先压缩（最长边 1600px、转成 JPG，通常只有几百 KB），再上传到仓库的 `public/uploads/YYYY-MM/` 目录；文件名自动生成（毫秒时间戳 + 转成英文/数字的原名）。GIF 动图不压缩，原样上传。
5. 上传完成后，正文里会自动出现类似 `![](/uploads/2026-11/1712345678901-cat.jpg)` 的图片标记。

说明：

- 封面图：在「更多设置」里点「上传封面」，选完会自动把路径填进「封面图」。
- 一次可以选多张（相册多选 / 粘贴 / 在电脑上把图拖进输入框），会按顺序逐张上传并插入。
- 图片稍大时多等几秒，看到正文插入标记才算传完。
- 网页里的路径要用 `/uploads/...` 开头，**不要写** `public/uploads/...`——`public` 是仓库目录名，不是网址前缀。
- 图片文件本身也提交进了仓库，相当于顺手做了一次备份。

### 5.6 图片库：复用和清理已上传的图

编辑器底部有个「图片库」按钮，会列出 `public/uploads/` 下所有上传过的图片（缩略图 + 文件名 + 大小）：

- **插入正文**：把 `![](/uploads/…)` 写到光标位置，同一张图不用重复传。
- **设为封面**：直接填进「封面图」字段。
- **上传新图**：一次选多张，传完自动刷新。
- **删除**：从仓库里删掉这个文件；如果已经有文章在引用它，那些文章会显示不出图（Git 历史里还能找回）。

图片库只是读取目录，不会改动文章；删除是不可撤销的，确认框里会再问一次。

### 5.7 保存前先预览

点正文工具条右侧的「预览」，正文会变成渲染后的样子，按钮也变成「继续写」；再点一下「继续写」回到编辑。这只是写作台里的预览，不会发布，也不影响仓库。

## 6. 预览、查看 GitHub 文件、删除

- **预览**：正文工具条右侧的「预览」按钮，在写作台里渲染 Markdown，检查标题、列表、图片有没有问题；再点「继续写」回到编辑。只是预览，不会发布。
- **查看 GitHub 文件**：编辑器底部的按钮（编辑已有文章时才出现），跳到 GitHub 上对应的 `.md` 文件。想确认提交内容、看文件历史，可以在这里操作。
- **图片库**：编辑器底部的「图片库」按钮，见 5.6。可以复用已上传的图、设为封面、删除不再用的图。
- **删除文章**：编辑器底部的红色「删除文章」按钮（新文章没有）。确认框会告诉你「将删除 src/content/blog/<文件名>.md。Git 历史里还能找回，但站点上会立刻消失（重新构建后）」，点「删除」才会删。后悔只能去 GitHub 的提交历史里找回旧版本。

## 7. 保存、发布和草稿

### 7.1 「保存」就是提交

点顶部「保存」后，写作台会把文章提交到 GitHub 的 `main` 分支。 **保存 = 提交 = 触发构建**：

1. GitHub 上多一条提交；
2. Netlify 检测到 `main` 有新提交，自动构建（通常 1 分钟左右，取决于排队情况）；
3. 构建成功后 https://lastembryo.netlify.app/ 更新。

保存成功会提示「已提交《标题》到 GitHub，Netlify 大约 1 分钟后更新站点」，提示里的「查看提交」可以打开这次 commit。提交信息由写作台自动生成，不用你写：

| 你做的操作 | 自动生成的提交信息 |
| --- | --- |
| 新建文章 | `post: 新增《标题》` |
| 修改文章 | `post: 更新《标题》` |
| 删除文章 | `post: 删除《标题》` |
| 修改文件名 | `post: 重命名《标题》`（旧文件会一起删掉） |
| 上传图片 | `assets: 上传图片 文件名` |
| 删除图片（图片库） | `assets: 删除图片 文件名` |

改名不会留下两份文件：新文件名和旧文件的删除会在**同一个提交**里完成。万一保存时提示「文件在别处被修改过」（409），说明这台设备打开编辑器之后，文件被另一处改过。写作台会先问你要不要覆盖，覆盖前会把被覆盖的远端版本存一份到本机草稿，后悔了还能从列表页的草稿里找回来。

**保存时断网**：内容会立刻写进本机草稿，页面提示「网络不通，内容已存成本机草稿」。等有网了打开这篇，选「恢复」再点保存即可，不用重写。

### 7.2 草稿：写一半先存着

打开「存为草稿」再保存，文章的 frontmatter 会写成 `draft: true`。

- 生产站**完全不会生成这篇**：首页、文章列表、归档、标签、RSS、sitemap、搜索里都没有它；直接打开 `https://lastembryo.netlify.app/blog/<文件名>/` 会 **404**。这是正常的草稿行为，不是 bug。
- 在电脑上的本地开发环境里（`npm run dev`）可以直接访问草稿并看到 `draft` 标记。
- 写完后关掉「存为草稿」，再点「保存」，等构建完成就正式上线。
- 手机上想先看效果，点正文工具条右侧的「预览」。

### 7.3 置顶

打开「置顶」再保存，文章会出现在首页的置顶区和列表最前面。

### 7.4 文章和图片落在哪里

| 内容 | 仓库位置 | 说明 |
| --- | --- | --- |
| 文章 | `src/content/blog/<文件名>.md` | 文件名就是网址的一部分 |
| 正文图片 | `public/uploads/YYYY-MM/` | 按上传月份建子目录 |
| 封面图 | 同上 | `cover` 字段指向 `/uploads/...` |

每次保存都是一次 git 提交，所以旧版本永远能找回：GitHub 仓库 → 文件 →「History」，或看仓库的 Commits 列表。

## 8. 令牌安全

令牌等于仓库的写权限，请按密码对待。

- **只存本机**：令牌只保存在这台手机浏览器的 localStorage 里，不会写进仓库，也不会随文章提交。
- **有效期**：建议 90 天换一次；只在私人手机上连接。令牌保存超过 80 天，写作台会在打开时提醒你提前换新。
- **公共设备**：在别人的手机或电脑上用过后，先到「设置」里点「断开连接」，再回 GitHub 删掉这个令牌。
- **怀疑泄露就吊销**：GitHub → 右上角头像 →「Settings」→「Developer settings」→「Personal access tokens」→「Fine-grained tokens」→ 找到这个令牌 →「Delete」（或「Revoke」）。吊销后旧令牌立即失效，写作台会报 401，重新生成一个令牌重新连接即可。
- 不要把令牌贴在截图、聊天记录、文章里；备忘录里那份用完可以删掉。

## 9. 故障排查

先看报错里的状态码：

| 状态码 | 常见原因 | 怎么办 |
| --- | --- | --- |
| **401** | 令牌无效：复制不全、已过期、已在 GitHub 吊销 | 到「设置」点「测试连接」；不行就重新生成令牌，粘贴后重新连接 |
| **403** | 权限不够（Contents 没选 Read and write、Resource owner / 仓库选错），或 GitHub API 请求太频繁 | 回 GitHub 检查令牌权限；如果是请求太频繁，等几分钟再试 |
| **404** | 仓库、分支、文章目录填错，或令牌无权访问该仓库；也可能是线上 `/admin/` 还没部署 | 「设置」里核对 `chenjing185/My_blog_website`、`main`、`src/content/blog`；部署问题看 Netlify 的 Deploys |
| **409** | 冲突：你打开编辑器期间，这个文件被别处改过（电脑或另一台手机） | 会弹「文件在别处被修改过」：选「取消」，返回刷新后再改；只有确定屏幕上的版本更新，才选「用我的版本覆盖」 |
| **422** | GitHub 拒绝了这次提交：内容或参数不合法，或分支在你提交前又被别处更新了 | 检查标题/摘要是否为空、日期格式和标签写法；提示「分支在你提交前又被更新了」时刷新后重试 |

其他常见问题：

- **列表上方出现「本机有未保存的草稿」**：说明这台手机上还有没提交的内容（自动草稿、断网时保存失败、或覆盖冲突时留下的远端备份）。点「继续写」打开，确认内容后点保存就提交了；点「丢弃」则删掉这份本机记录，仓库不受影响。
- **提示「令牌是 N 天前保存的」**：只是提醒。细粒度令牌通常 90 天到期，提前去 GitHub 生成新的、到设置里替换即可。
- **断网了还能写吗**：能打开写作台（Service Worker 缓存了页面），也能写、会自动存本机草稿，但保存到 GitHub 需要网络；联网后打开这篇选「恢复」再保存。

- **保存成功但站点没变**：Netlify 构建通常要 1 分钟左右。打开 <https://app.netlify.com>，进站点 →「Deploys」，看最新一次是不是 Success；失败就点进去看 Deploy log。
- **构建失败**：多数是 frontmatter 写错。常见原因：
  - 标题超过 120 字、摘要超过 300 字；
  - 日期写成 `2026/11/10` 或「11月10日」（必须 `2026-11-10`）；
  - 手动改 `.md` 时把 `tags` 写成了普通文字，正确写法是 `tags: ['随笔', '手机']`；
  - `cover` 或正文图片路径写错。
- **图片不显示**：正文里必须是 `/uploads/YYYY-MM/文件名.jpg`；不要带 `public/`；注意文件名大小写。
- **草稿发出去线上是 404**：正常，见 7.2。
- **列表里没有刚保存的文章**：先确认 Netlify 构建成功，再检查是不是还开着「存为草稿」。
- **「预览」和线上不一样**：预览只是写作台里的渲染；真正的站点效果要等构建完成。
- **换手机后打不开文章/提示没有草稿**：本地草稿和令牌都只在这台手机上，换设备看不到，也不影响仓库里的文章。
- **提示「网络请求失败」**：手机网络不稳，或代理拦截了 api.github.com；换 Wi-Fi / 移动网络再试。

## 10. 速查

### 10.1 常用路径

```
文章        src/content/blog/<文件名>.md
文章网址    /blog/<文件名>/
正文图片    public/uploads/YYYY-MM/文件名.jpg
图片引用    /uploads/YYYY-MM/文件名.jpg
写作台      /admin/
演示模式    /admin/?demo=1
离线脚本    public/admin/sw.js
```

### 10.2 frontmatter 字段（schema 定义在 `src/content.config.ts`）

| 字段 | 必填 | 类型 / 限制 | 作用 |
| --- | --- | --- | --- |
| `title` | ✅ | 字符串，最长 120 字符 | 文章标题 |
| `description` | ✅ | 字符串，最长 300 字符 | 摘要，列表卡片 / RSS / SEO |
| `pubDate` | ✅ | 日期，如 `2026-11-10` | 发布日期，影响排序 |
| `updatedDate` | | 日期 | 显示「更新于」 |
| `category` | | 字符串 | 单值分类，生成 `/categories/<slug>/` |
| `tags` | | 字符串数组，默认 `[]` | 标签聚合 |
| `series` | | 字符串 | 同名文章聚合成专栏 |
| `draft` | | 布尔，默认 `false` | `true` 时生产构建不生成该文章 |
| `pinned` | | 布尔，默认 `false` | 置顶 |
| `cover` | | 字符串 | 列表缩略图，也用作分享图 |
| `link` | | URL | 外链文章，在「更多设置 → 外链」 |
| `subtitle` | | 字符串 | 标题下的副标题，在「更多设置 → 副标题」 |

字段写错或超长，构建会直接报错——这是有意的，避免线上出现空标题。

手写一篇的完整示例：

```yaml
---
title: 手机写的第一篇
description: 用写作台在手机上发文章，全程不用电脑。
pubDate: 2026-11-10
updatedDate: 2026-11-11
category: 随笔
tags: ['随笔', '手机']
series: 建站笔记
draft: false
pinned: false
cover: /uploads/2026-11/1712345678901-cat.jpg
---
```

### 10.3 电脑上常用命令

```bash
# 需要 Node.js >= 22.12.0
npm install        # 安装依赖
npm run dev        # 本地预览 http://localhost:4321（能看到草稿）
npm run build      # 构建到 dist/
npm run preview    # 预览构建产物
```
